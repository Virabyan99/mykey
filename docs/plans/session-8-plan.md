> **For the executing agent:** carry this plan out run by run, in the order given in "Run order" — which is **not** the number order of Doc 10. If you have the superpowers skills, use `superpowers:executing-plans` (inline execution is the owner's standing preference; the fresh-context reviews of Run 8.5 are the session's review). You do not re-decide anything in Doc 10 §3 / §8 or in the "Planner decisions" table below; if one proves wrong, write a one-paragraph decision record and continue (Doc 10 §1). **This plan keeps Session 7's light cadence** (D-58; the owner, 20 Nov 2026): read "How this session is tested" before anything else, and do not add a suite run, a release, a deploy or a review that it does not name.

**Goal:** By the end of 22 November 2026: one build has been attacked from a second organization, swept for every kind of secret, and read by reviewers that did not write it; every finding rated high or critical is fixed; all 56 release scenarios and all 29 proofs are bound to that one build in one manifest; the owner has walked the first-run path; production runs the build, closed and ready to be opened; and the owner has signed Gate R.

**Architecture:** Session 8 builds almost nothing new. It has four kinds of work, and the order is chosen so that the heavy proof runs **once**. (1) Before anything is frozen, everything that is already known to change the build goes in: the carried findings, and three gaps that would stop production from ever being opened. (2) Still before the freeze, the two new proofs are written and run against what exists (the attack suite locally, the sweep once on staging's current build), and six reviewers read the code in parallel. (3) What they find is fixed, one reviewer reads the fixes, and only then is the candidate frozen: one release, built from a commit that is already green on the full suite, deployed to staging and to production (closed). (4) On that candidate, once: every staging file, the consumer rehearsal, the cloud tests, the CLI on four platforms, the sweep, the owner's hour; then one manifest that binds each scenario and proof to the test files that proved it, and Gate R. Doc 10 freezes first and fixes afterwards, which builds every release twice; this plan fixes first and freezes once (P-143).

**Tech stack:** everything pinned in Sessions 1–7. No new dependency. One setting of OpenBao is used for the first time (`user_lockout` in the server configuration, P-149).

Rules that follow from it:

- **No full suite, no release, no deploy and no staging pass before the freeze.** Not "to be safe". The two exceptions are named in the first row.
- **Nothing that can change the build is left for after the freeze.** A defect known today is fixed in Run 8.0, a defect found by an attack, the sweep or a reviewer in Run 8.6. That is why the freeze comes sixth.
- **A change after the freeze costs what P-145's table says, and no more.** A repaired test does not make a new candidate. A product defect makes `host-v0.8.1`, once; a second one stops the session and goes to the owner.
- **A run's tests are the ones this plan names.** Ideas for more go into the run note under `Open issues`.
- **A failing attack or a found needle is a finding, not a broken test.** It is written down with its evidence and fixed in Run 8.6, test first. A test is never weakened to pass; a staging test that is stale against Sessions 6–8 is repaired as a test, and the run note says why it was stale.
- **Everything runs at this gate.** D-58's rule that leaves `test:cloud` and the CLI out when their code did not change does not apply to Gate R: Session 7's plan promised them here.
- **Run notes are short:** the five headings of Run 1.1's template, ten to twenty lines, with the test counts and the commit ids. The evidence files of this session are the ones the file map names, and no other.

What is **not** made lighter: Doc 10 §4.1; test first for every fix; real stores as proof; the sweep and its controls; the six reviews and the re-read of the fixes; every staging file on the candidate; the manifest's check; the owner's signature.

## Global constraints

Every run's requirements include this section and the "Global constraints" of the plans of Sessions 1–7.

- **Doc 10 §4.1, as this session can break it.** Rule 2: a needle of the sweep, a custody value or a reset link in a run note, a review file, an evidence file, a CI log or this conversation — the sweep's files hold counts and names, never a value; the owner opens a reset link's file themself. Rule 10: no real secret anywhere, and **production gets no account, no organization and no data in this session**. Rule 11: a scenario marked `PASS` without a green result on the candidate behind it; a reviewer's "none found" reported for code the reviewer did not read.
- **A pass is a pass on the candidate (P-144).** No status is raised by argument. An item whose proof needs a calendar or a clean server keeps its earlier evidence, and the manifest and Gate R's report name it as such.
- **Unacceptable substitutions (Doc 08 Part IV B).** Never: a unit test in place of a real unseal; an upload in place of a restore; an expiry claim in place of real lock ageing; a client timeout in place of exclusion; the page's hidden button in place of OpenBao's own denial; a partial read in place of a complete one; a create answer in place of a revocation proof; a screenshot in place of a used workflow.
- **The restore code is not changed in this session (P-150).** `scripts/host-restore.ts`, `apps/ops/src/commands/restore*`, `packages/backup` and the restore's part of `host.ts` stay as Run 6.8's drill proved them, unless a reviewer rates a restore finding high or critical. A change there is named in Gate R's report, and Run 9.7 then repeats the drill.
- **The route list stays frozen (D-15).** No route, no contract change, no migration is expected. If a fix needs a migration it is `0019`, expand-only, with the privilege matrix and the inventory in the same commit, and the run note says what the rollback rehearsal (`deploy.staging`) then proves.
- **The reviewers are independent (D-06).** A reviewer gets the paths, the questions and `known-limits.md`. It does not get this plan, the run notes or your opinion of the code. Its text is saved as it came.
- **Staging and production.** Staging is touched once before the freeze by each new staging file, and then at the freeze. Production is changed only with the owner's yes of the session start, only by the commands of Run 8.1, and its gate is never opened here.
- **The workstation.** One heavy job at a time: a release build, `test:consumers` and a local browser or integration file never run beside each other. Quit Chrome before the release build (Session 7's gate stopped twice for memory). Staging files are light on the workstation: documents may be written while one runs. Regexes and escapes are written with the editor tools, never through the shell.
- **Git.** Branch `session-8`, never `main`. The pull request is opened as a draft after Run 8.0's first push and merged only when the owner says so.
- **Every run ends with:** `pnpm run check` green, the run's tests green, a commit, a push, and a run note `docs/evidence/session-8/run-8.N.md`.

## Review focus

Five conditions the specifications imply but do not spell out, most likely to bite first. Each has a test or a step pinned in the run named.

1. **The signed build cannot be opened.** Gate R is signed, Run 9.1 starts, and the tool refuses production's OpenBao, or the deploy report cannot be made for a real owner on an empty host. The fix then changes the build the owner has just signed. → P-146, P-147: Run 8.0 Task B and its three tests; Run 8.1 Task A does the fresh-host path on production itself before the freeze.
2. **Evidence that is not about the candidate.** A green of an earlier build counted as a pass; a test repaired after the freeze by asking less; a fix made after the review and read by nobody; a reviewer's "high" graded down by the author. → P-144, P-145, P-153: the manifest's check compares commits and refuses a missing result; one reviewer reads the fixes; a severity changes only with an executed test.
3. **A sweep that cannot find anything.** The needles travel one way and the controls another; the dump is compressed; the journal is read for a window that ended before the request; a six-digit code matches every timestamp. → P-152: every surface has a control that is sent exactly as the needles are, and the sweep's header says what it cannot see.
4. **Isolation proven on stubs.** The matrix asks stub handlers; the real handlers have never met a second organization that has a namespace of its own. → P-151: both organizations are provisioned, each behind its own real API, and one test reads OpenBao's audit device to show that nothing of A's requests reached B's namespace.
5. **The gate's own steps break the gate.** The owner's hour replaces the test owner's authenticator; two things sign in from one address and spend each other's five sign-ins a minute; a stale test leaves a closed gate (Session 6) or a host that does not come back (Session 7). → P-155 and the order of Run 8.7: the owner's hour is alone on staging, the test owner is re-established and proven before the pass, the files that stop services run last, and `status` is read after each of them.

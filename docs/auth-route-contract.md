# Auth route contract

Generated by `node scripts/auth-route-contract.ts` from `@mykey/auth`. Do not edit by hand; `pnpm run auth:contract:check` fails when this file is stale. Decision record: `docs/decisions/D-19-auth-storage-design.md`.

- **Library:** better-auth 1.7.19, password sign-in and sessions only. No catch-all handler is mounted (P-25); every route below has its own handler, and every other path under `/v1/auth` answers `404 not_found`.
- **Session cookie:** `__Secure-better-auth.session_token`, attributes `{"secure":true,"sameSite":"strict","path":"/","httpOnly":true,"maxAge":43200}`. Its value is `<token>.<signature>`, signed by Better Auth; the database stores only `v1.<keyId>.<HMAC>` of the token (P-26).
- **Errors:** the contract envelope `{ error: { code, message, requestId } }`. A wrong, a replayed and an expired code get the same answer.
- **Origin check:** product (Run 3.7). `auth.api` calls bypass Better Auth's own Origin and CSRF checks, which stay enabled in its options.
- **Throttling:** product (Run 3.3). Better Auth's limiter is off.

## Served routes

### POST `/v1/auth/sign-in/email` (native)

- **Request body:** `{"type":"object","properties":{"email":{"type":"string","maxLength":320,"format":"email","pattern":"^(?:[A-Za-z0-9_'+\\-]+\\.)*[A-Za-z0-9_'+\\-]*[A-Za-z0-9_+-]@(?:[A-Za-z0-9][A-Za-z0-9\\-]*\\.)+[A-Za-z]{2,}$"},"password":{"type":"string","minLength":1,"maxLength":1024}},"required":["email","password"],"additionalProperties":false}`
- **Success:** 200, exactly `{"phase":"password_verified"}` (Run 3.2)
- **Errors:** 400 `malformed_request` (body not JSON, a field missing, an unknown field); 401 `unauthenticated`, byte-identical but for the request id, for an unknown e-mail, a wrong password, an account that is `disabled` or `recovery_pending`, and an epoch that moved during the sign-in; no cookie, no session row; 503 `audit_unavailable` (the audit row could not be written; no session remains)
- **Cookies:** sets the session cookie of a new `password_verified` session bound to the account's current auth epoch; `Max-Age=43200`
- **Account states:** `enrollment_pending` or `active`
- **Session phases:** none needed; creates `password_verified`
- **Origin check:** product (Run 3.7)

### POST `/v1/auth/change-password` (native)

- **Request body:** `{"type":"object","properties":{"currentPassword":{"type":"string","minLength":1,"maxLength":1024},"newPassword":{"type":"string","minLength":1,"maxLength":1024},"revokeOtherSessions":{"type":"boolean"}},"required":["currentPassword","newPassword"],"additionalProperties":false}`
- **Success:** 200, `{ user }` without `token`
- **Errors:** 400 `malformed_request` (body not JSON, a field missing, an unknown field); 401 `unauthenticated` (no session, or wrong current password); 401 `mfa_incomplete` (session not `mfa_complete`)
- **Cookies:** with `revokeOtherSessions: true`: every session of the user is removed and a new `password_verified` session cookie is set (observed on 1.7.19, D-19); the owner passes the factor again
- **Account states:** any (Run 3.5 adds fresh verification)
- **Session phases:** `mfa_complete`
- **Origin check:** product (Run 3.7)

**Dated init answers (Run 9.7).** Beside a host's `openbao-init.json`, `~/.mykey/custody/<host>/` may hold `openbao-init.<UTC stamp>.json` files. None is ever overwritten. There are two kinds:

- **A new server's own answer.** `bao-init` writes it there when the copy still holds a lost host's answer: a host restored onto its own reinstalled server.
- **A replaced copy.** `restore-verify --open` keeps the copy it replaced there.

After a restore, `openbao-init.json` is the **source's** answer (its recovery key) with the restored OpenBao's new root token. A dated answer's root token opens nothing once a snapshot has replaced that OpenBao's store, and neither does its recovery key. Keep them until the restored host has taken and verified its own pairs. The password manager's copy follows `openbao-init.json`.

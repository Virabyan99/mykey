# Custody map — what it takes to rebuild staging

One row per thing without which staging cannot be rebuilt or its data read again. Names and places only; values never appear here (see `credential-custody.md` for every credential). Written in Run 2.7; production gets its own map at its first OpenBao start.

| What                                                              | Kept at                                                                        | Second place                                                                                    | Who can reissue it                                                                        | Expires                              |

| Seal key `mykey-staging-seal-1` (`5ec11f05-…`)                    | OVHcloud KMS, domain `mykey-staging-kms` (`9d3293d1-…`)                        | None — it cannot leave the KMS (`Never Extractable`). Its loss loses every byte sealed with it. | Nobody. Only rotation to a new key while the old one still exists (`kms-and-unseal.md`)   | No expiry; destroyed only on purpose |
| Seal certificate `staging-seal-1` and its key                     | Staging host, `/etc/mykey/secrets/kms/`                                        | Certificate also in `~/.mykey/kms/`; the key has no copy (by design)                            | Owner in the OVHcloud console, from a new CSR made on the host                            | **12 Dec 2026, 09:16 UTC** (30 days) |

# Run 2.5 — Host hardening and network skeleton

**Result: DONE on 11 Nov 2026.** Two OVHcloud US VPS run Ubuntu 24.04.4 behind a default-deny nftables table, reachable for the operator only through WireGuard, with SSH on the VPN address only. Each serves `GET /health` of the API stub through Traefik with a Let's Encrypt certificate; the API reaches PostgreSQL over TLS verified against the host's own CA. From the internet only TCP 443 answers (and UDP 51820, proven by the tunnel); spoofed forwarded headers, plain HTTP, TLS 1.1, unknown server names, plaintext PostgreSQL and an API certificate from another CA are all refused; a reboot restores everything with no command typed. Decision record: D-21.

FR-1.70 SPIKE_PASS — staging exists as a separate host built by the same tool and the same files as production (`scripts/host.ts`, `infra/hosts/**`, `infra/compose/host*`), with its own name, certificate and VPN address; destructive drills (revert, reboot, certificate swap) ran on staging only. Missing for PASS: the deployed release configuration (Run 6.9).

FR-1.71 SPIKE_PASS — every hop that exists in Session 2 is TLS, verified: client → edge (Let's Encrypt, TLS 1.2+, HSTS), edge → API (host CA, name `api`; with an API certificate from another CA the API still answers on its bridge address, the host CA rejects it, and the proxy answers 500 every time), API and operator → PostgreSQL (TLS 1.3, host CA; plaintext refused by `pg_hba`). Missing for PASS: the OpenBao and KMS hops (Run 2.7) and the CLI (Run 5.5).

FR-1.72 SPIKE_PASS — host boundary: one default-deny table, SSH VPN-only and key-only, containers non-root, read-only, without capabilities, with memory and process limits and no Docker socket; egress per purpose to address sets; `api` and `postgres` have no route out (`tests/staging/boundary.staging.test.ts`).

AC-1.30 SPIKE_PASS — public HTTPS with a valid Let's Encrypt chain for the host name, `strict-transport-security: max-age=63072000` without `includeSubDomains`, TLS 1.1 refused by the server, TLS 1.2 and 1.3 accepted, on staging and production (`tests/staging/transport.staging.test.ts`). Missing for PASS: "the CLI cannot bypass TLS" (Run 5.5).

AC-1.31 SPIKE_PASS — external exposure is HTTPS plus the WireGuard exception: a full TCP scan and a UDP scan of both public addresses show 443/tcp as the only open port; 51820/udp is proven by the working tunnel (`docs/evidence/session-2/host-scan-*.txt`). Missing for PASS: the same scan of the release deployment (Session 8).

PO-11 SPIKE_PASS — Node permission behaviour: the API image runs as `node --permission --allow-fs-read=/app --allow-fs-read=/run/mykey`, read-only, with all capabilities dropped; Hono, `@hono/node-server`, `pg` and type stripping work under it on both hosts. The permission model does not restrict the network (observed); the network limit is the firewall. Missing for PASS: the local Scalar page and the browser CSP (Sessions 5 and 7).

## Deviations and decisions

Rulings R15 to R32 of the session ledger concern this run; each is summarised here.

- **R15** NTP from two fixed Cloudflare anycast addresses through chrony (the VPS was given none). **R16** a `blocked` set with kernel timeouts, checked before `established`. **R17** `apply-with-revert.sh` takes command strings. **R18** production bootstrapped right after staging so the tunnel file holds both peers (one Windows prompt). **R19** extra status fields (`chronyOffsetMs`, `clockSynced`, `firewall`, `sshListen`). **R20** the host may reach the OpenStack metadata service (TCP 80, `169.254.169.254`).
- **R21** `@hono/node-server` 2.1.6, not 2.1.7 (published on the day of pinning). **R22** `/health` shares one reading for 1 s over a pool of one connection. **R23** Traefik's static configuration as flags in Compose; there is no `traefik.yml`. **R24** host `pg_hba` allows the socket inside the container with a password. **R25** the node image is the alpine flavour.
- **R26** images travel in 2 MiB parts over eight SSH connections, checksum before `docker load`: the upload direction loses 6 to 23 % of packets (ping through the tunnel: 23 % at 1,392 bytes, 6 % at 64 bytes); one stream ran near 40 kB/s, eight moved 66 MB in 61 s. A lower tunnel MTU (1,280) made no difference.
- **R27** the maintenance window refreshes the `registry` set every 2 s, and `production.cloudfront.docker.com` was added: the first pull failed because Docker Hub served layers from CloudFront. `docker pull` tries IPv6 first; the firewall refuses it and the pull falls back to IPv4.
- **R28** `host.ts <host> acme <staging|production>`; bootstrap sets the directory only when it is absent. The first switch failed safely (`volume is in use`: the finished `pki-init` container held the ACME volume); the command now removes it too. Without dropping the volume, Traefik logs `Account URI does not match the current CAServer` and keeps serving the staging certificate.
- **R29** `up` creates the two host secrets (PostgreSQL superuser, owner 999; `api_runtime`, owner 1000; directories 0700, files 0400) before Compose; the other four role passwords stay on the workstation.
- **R30 — the workstation's network answers TCP 53 for every address.** Nmap and a plain `connect()` both see 53/tcp open on `192.0.2.1` and `198.51.100.77`, where nothing can listen. The scan cannot judge that port from here, so the boundary test asks the reserved address `192.0.2.1` and checks every such port on the host instead. The interception is not steady: in a scan of several ports `192.0.2.1` showed 53/tcp `filtered`, while a single-port probe a moment later showed it `open`; the test therefore asks again up to three times, one port at a time. On the host: no listener outside loopback (only `systemd-resolved` on `127.0.0.53` and `127.0.0.54`), no input rule for it. UDP 53 behaves the same. A scan from a neutral place (the probe Worker of Run 2.6 can open TCP sockets) can close the gap.
- **R31 — the allowed-name control of the host egress check uses the R2 endpoint** until `mykey-probe.nomikey.com` exists (Run 2.6); the probe name then joins the same assertion.
- **The full scan uses `--min-rate 1000`.** With nmap's default timing over this lossy path a full TCP scan had not finished after 17 minutes; at a minimum of 1,000 probes per second with three retries it takes about 135 s. 443 is the control: a dropped probe can only make the scan fail, not pass.
- **R32 — the proxy answers 500, not 502 or 503, when the API certificate does not verify.** The plan expected 502 or 503 and a certificate error in Traefik's log. Traefik 3.7.17 logs the TLS cause at debug level only, and the first drill run saw 502 — which turned out to be the API still restarting. The drill now proves the cause step by step: the API answers on its bridge address without verification (`curl -k` 200), the host CA rejects its certificate (`curl --cacert` exit 60), then the public `/health` answers 500 three times and the access log records them; after the restore the host CA accepts the certificate again (control). Keeping Traefik at its default log level is deliberate (no debug output on a host).
- **PostgreSQL 18 words the plaintext refusal** `pg_hba.conf rejects connection for host "10.78.2.1", user "postgres", database "postgres", no encryption` (code 28000): the explicit `host all all all reject` line matched, which is the intended reason.
- **`X-Request-Id` and `forwardedProto`.** The transport test finds the log line of its own request by id; the API now returns the id and logs `X-Forwarded-Proto` as received (informational, nothing trusts it). The proxy replaces both forwarded headers: the log shows the workstation's public address (its WireGuard endpoint as the host sees it) and `https`.
- **Container DNS, observed with Docker 29.1.3:** on `mk-pub` public names resolve; on the internal bridges they do not; a query to another resolver fails from every bridge. No rule was added.
- **The registry note in the plan for AC-1.31** names TOTP drift; the registry title of AC-1.31 is "External exposure matches HTTPS plus WireGuard exception", which is what this run proves. The note above follows the registry.
- The registry is not edited in this run (ruling R6).

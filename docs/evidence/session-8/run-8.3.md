**Checked against the acceptance criteria.**

- **AC-1.38:**
  - kills at intent, dispatch, backend success and final commit: secrets boundaries (six points);
  - a backend request delayed past the timeout: delays;
  - reconciliation and retry, with and without exclusion: delays ("nothing lands; settled rejected" with exclusion; "undetermined; lands; succeeded" without it, so no false no-effect rejection);
  - no duplicate executor: effects/exclusion.
- **AC-1.40:**
  - the issuance answer lost at each boundary: issuance;
  - an unfinished retry returns status, and a successful replay returns no token and creates none: issuance (after the finalize: `409 credential_not_replayable`, no token);
  - a verified rejected replay stays rejected: issuance (`rejected`, then the replay answers without a token);
  - delayed creation excluded before the inventory completes: issuance (the late create and `reconcile-credentials`);
  - archive races: archive.
  - **Replacement races had no test of their own.** Written now: `protocol.test.ts`, "a replacement issued while the old credential is revoked (20 rounds)". Both requests run at once on two API processes. After each round the new credential is the only active one, the old one is `revoked`, and the catalog matches the backend. It passed at its first run (13/13 for the file), so the behaviour held already; this closes a gap in coverage, not a defect. It is a test only, so it changes nothing of the candidate.

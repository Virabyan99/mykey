# D-36 — The secret mutation protocol

**Date:** 2026-11-13

**Status:** DECIDED in the Session 4 plan (P-62, P-66 … P-72), recorded by the executing agent in Run 4.2. Evidence: `tests/integration/secrets/{create,update,capacity,protocol}.test.ts`, `tests/integration/database/privileges.test.ts`, `tests/unit/audit/events.test.ts`, `docs/evidence/session-4/run-4.2.md`.

## Decision

- **One lock per environment, on its own connection.** Every secret mutation takes `pg_advisory_lock(environment.lock_key)` on a connection from a dedicated lock pool (8 of the API's 20 connections) and runs all of its transactions on that connection (`withEnvironmentLock`). The pool and the lock are each waited for at most 2 s (`LIMITS.deadlines.poolAcquireMs`, `advisoryLockMs` as `lock_timeout`); either wait running out answers `503 busy` with no operation. A connection that reported an error, or whose unlock or reset failed, is destroyed instead of returned to the pool, so a lock never outlives its request on a pooled connection.
- **Order, all under the lock** (`runSecretAction`): (a) pre-read of the key's backend metadata; (b) admission transaction: insert the operation `accepted` with its scope, name, expected version and this process's boot id (an existing key replays or answers `idempotency_conflict`); capture mode `idle` `FOR SHARE`; the parents locked and the caller's authority and states re-read (FR-1.10: the API passes this recheck as a callback built from `lockParents`, `resolveAccess`, `decide` and `checkStates`); the environment's effect slot; the index row `FOR UPDATE`; the action's checks; capacity; the step row with `before_state`; the slot; audit `intent`. Any refusal rolls the whole transaction back and leaves no operation. (c) Dispatch transaction: `claimDispatch`, a fresh dispatch attempt id on the step, capture mode still `idle` and the gate still open — otherwise the operation is closed `rejected` (`busy` or `quarantined`) with its slot released. The commit of this transaction is the dispatch marker. (d) One KV change, carrying `x-mykey-operation-id` and `x-mykey-dispatch-id`. (e) Read-back: the written version's envelope names this operation. (f) Finalize: counters, operation `succeeded` with `{ name, version, stateTag, state, generation }`, index row with a fresh tag, version event, audit `success`, slot released.
- **After the marker every failure is unknown.** An unclear backend answer, a failed read-back, a lost lock, or any throw answers `503 outcome_unknown` with the `operationId`. Where it can, the protocol records the operation `uncertain`, the key `needs_review` and an audit row `unknown`, and keeps the slot. If that record cannot be written, the operation stays `executing` for the sweep (Run 4.5). The conditional finish (`executor_boot_id`, state) means a finished operation is never overwritten.
- **Definite backend answers to the change** (P-68): `cas_mismatch` → `rejected backend_inconsistent`, key to review; `denied` → `rejected backend_inconsistent`, environment to review (`app.mark_environment_review`, the one way `api_runtime` can set that state, migration `0012`); `sealed` → `rejected backend_sealed`; `invalid` with status 0 (never connected) → `rejected dependency_unavailable`. Every other `invalid` and every `unknown` → `uncertain`. A pre-read that is `denied` sends the environment to review and audits `system.drift_detected` (`kv_data`).
- **The effect slot** `env:<environmentId>` is per environment. While another operation holds it, every mutation of that environment answers `409 key_under_review` with the holder's `operationId` (P-67). A slot is released only by its operation's finalize or by reconciliation.
- **Checks.** Create: an index row in any state → `already_exists`; no row but backend history → key to review and `backend_inconsistent`; at 1,000 names (deleted names count) → `507 { limit: "names" }`; live bytes over 8 MiB → `507 { limit: "bytes" }`; sends `cas: 0`. Update: no row → `404`; row in review → `key_under_review`; deleted → `state_conflict`; version or tag differ → `409 version_conflict { currentVersion, currentStateTag, state }`; the backend's current version not the index's, or deleted → key to review and `backend_inconsistent`; bytes → `507`; sends `cas: expectedVersion`. A state tag is 16 random bytes in base64url and changes with every write.
- **No runtime identity, no secrets.** A process without the runtime credential, or whose credential belongs to another organization, answers `503 dependency_unavailable` on every secret route.
- **Body shape.** An update body missing `expectedVersion` or `expectedStateTag`, or carrying an unknown key, is `400 malformed_request` (Doc 06 §9, as the pipeline does for every route), not `422`.

## What would change this decision

- Measurements on staging (Run 4.2 Task D) showing that 2 s of lock wait refuses ordinary use.
- A per-key slot instead of a per-environment one would let unrelated keys proceed while one is uncertain; Doc 06 §8 blocks the environment today.

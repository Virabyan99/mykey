# D-29 — Sessions, fresh verification and the product-owned password change

**Date:** 2026-11-12

**Status:** DECIDED in the Session 3 plan (P-49, P-50), recorded by the executing agent in Run 3.5. Amends D-19 (the native change-password). Evidence: `tests/integration/auth/{sessions,password,fresh}.test.ts`, `tests/unit/auth/routes.test.ts`, `docs/evidence/session-3/run-3.5.md`.

## Decision

- **One validity decision.** `resolveSession` (`packages/auth/src/sessions.ts`) is the only place a session is judged. It takes the token from the signed cookie (checking the signature with Better Auth's own signing and the cookie secret) and decides in one SQL statement, every comparison on the database's `now()`: absolute `authenticated_at + 12 h`; idle `last_user_activity_at + 30 min` for `mfa_complete`; challenge `authenticated_at + 10 min` for the other phases; the account's state fits the phase (`mfa_complete` → `active`; `password_verified` → `enrollment_pending` or `active`; `enrollment` → `enrollment_pending`; Run 3.6 adds the reset challenge); the auth epochs are equal. A row found past a limit is deleted in the same call. Product routes, the factor routes, the session routes and `GET /v1/auth/get-session` all decide through it; no other file calls Better Auth's `getSession` (a unit test searches the sources). `get-session` answers `null` for a session it refuses.
- **Activity.** `last_user_activity_at` moves on sign-in, factor completion, step-up and `POST /v1/session/activity` only — never on a GET or another mutation. `touchActivity` writes at most once a minute. `session.activity` (class `human`) answers `{ idleExpiresAt, absoluteExpiresAt }`; an expired session gets the pipeline's 401 and cannot revive itself.
- **Lists and revocation (P-50)** are product routes: `GET /v1/auth/sessions` → `{ sessions: [{ id, createdAt, lastActivityAt, client, current }] }` (`client` = the user agent cut to 120 printable ASCII characters); `POST /v1/auth/sessions/revoke { sessionId }` → 200, an id that is not the caller's is the same `404 not_found` as an absent one, revoking the current session equals sign-out. The native `POST /v1/auth/revoke-sessions` stays and ends every session including the current one. All need an `mfa_complete` session; no answer holds a token or a verifier.
- **Password change (P-49)** at `POST /v1/auth/change-password { currentPassword, newPassword }`, product code, the native endpoint never called (it is in `NATIVE_DENIED`; the path is `PRODUCT_OWNED`): the `password` throttle for the account's e-mail → one transaction locking the account and the session → fresh TOTP of this session (else `403 fresh_verification_required`) → the rule of P-46 (else `422 validation_failed`) → the current password against the stored hash with Better Auth's verifier (else the failure is counted and `401 unauthenticated`) → the new hash, `credential_epoch + 1`, every other session of the user deleted, audit `auth.password_change` → commit → `200 { revokedSessions }`. This session keeps its token and its phase; a sign-in that verified the old password before the change and commits after it is refused by its epoch check. `NATIVE_ALLOWED` keeps four routes.
- **Freshness.** Routes of class `human_fresh_totp` (`export.create`, `credentials.issue`) answer `403 fresh_verification_required` when the session's TOTP verification is older than 600 s or was never made (a recovery-code session), before the handler; freshness belongs to one session. With the password change and recovery-code regeneration these are the four sensitive starts of FR-1.77.
- **Clean-up.** The API deletes sessions past either limit or past the challenge limit at start and hourly (`cleanUpSessions`; Doc 04 §2.1 asks for daily). The API's role may not delete used TOTP steps or recovery codes (Session 2 withheld it so a compromised API cannot erase replay evidence); `ops auth-cleanup` (`cleanUpFactors`, as `maintenance`) removes steps older than a day, consumed codes and codes of retired enrollments. Its two `DELETE` grants come with migration `0006` (Run 3.6); a timer for it is Run 6.9.

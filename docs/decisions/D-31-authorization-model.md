# D-31 — Authorization model: one pipeline, current rows, hidden equals absent

**Date:** 2026-11-13

**Status:** DECIDED in the Session 3 plan (P-52, P-53), recorded by the executing agent in Run 3.7. Evidence: `tests/unit/authz/{decide,route-actions}.test.ts`, `tests/integration/authz/{origin,concealment,matrix,states,revocation}.test.ts`, `docs/evidence/session-3/authorization-matrix.md`, `docs/evidence/session-3/run-3.7.md`.

## Decision

- **Pipeline order** (Doc 06 §4.4), final: request id → gate → body limits → mixed-credential check → Origin check → authentication → strict validation of body and query → ancestry and membership → visibility → action → state → freshness → handler. Every contract route runs it through `mountRoute`; no handler checks authority itself.
- **Mixed credentials.** A request with the session cookie and an `Authorization` header is `400 mixed_authentication` on human and machine routes, before any database read.
- **Origin** (FR-1.76). Every non-GET request of class `human`, `human_fresh_totp` or `reset_flow`, and every POST under `/v1/auth` including sign-in, must carry `Origin` equal to the origin of the configured base URL; `Sec-Fetch-Site`, when present, must be `same-origin`. Otherwise `403 origin_rejected`, before the session is read and before any throttle counter moves. A missing `Origin` is a refusal. One implementation (`apps/api/src/pipeline/origin.ts`); the auth module receives it as `AuthRouteEnv.originAllowed`.
- **The contract carries the model.** Every human route names an `action` (`resources.manage`, `secrets.read`, `secrets.history`, `secrets.write`, `credentials.manage`, `audit.view`, or `null` when seeing is enough) and a `scope` (`none`, `organization`, `project`, `environment`, `operation`). `decide(authority, target, action)` in `@mykey/contracts` is Doc 04 §1.1 as a pure function: owner and admin are allowed everywhere in their organization; a member sees the organization, sees a project with a project grant or any environment grant in it, sees an environment through the stronger of its own grant and its project's (union; an environment grant never narrows a project grant), may read and see history wherever it sees, may write as an editor, and is denied every other action.
- **Current rows, no cache.** `resolveAccess` reads the active membership, every grant of the user in the organization and the states of the organization, project and environment named by the path, in one statement, on every request. A revoked membership, a removed or lowered grant, a revoked session or a disabled account takes effect on the next request.
- **Ancestry and concealment.** Path ids that are not lower-case UUIDs, or that do not chain (environment in project, project in organization), are `404 not_found` — the same answer, headers and length as an id that is not visible, and as one that does not exist. `hidden` → `404 not_found`; `denied` → `403 action_denied`. Each refusal is audited as `access.denied` with `{ routeId, reason: hidden | action | state | fresh }`; the organization id is recorded only when the caller is a member of it. Scope `operation` answers 404 until Run 4.1 defines its resolution.
- **States** (P-53) come after visibility and action, parent first: an organization `provisioning` or `failed` is `state_conflict`, `needs_review` is `backend_inconsistent` for every scoped route; project and environment states follow the table of the plan (pending: metadata ok, secrets only when `kv_ready`, no credential issue; revoking and archived: reads only; needs_review: metadata reads only, writes `state_conflict`, secret and credential routes `backend_inconsistent`). Archive, reactivate and credential revocation (class `lifecycle`) see only the organization row here; their own runs decide on resource states. `organizations.list` is not subject to it: it is how the owner sees the state, with `reviewReason` (migration `0007_review_reason`; the provisioner is its one writer).
- **Client-supplied selectors** (namespace, path, policy, role, organization) are refused by strict validation as `400 malformed_request`; a header claiming a role is ignored.
